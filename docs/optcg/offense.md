# 攻撃の技術 (攻撃順・DON付与・要求値・リーサル・情報戦)

> 攻めの操作術の集約。 前提となる思想は [README.md](./README.md) の統一原則 (手札を削るゲーム / NNA /
> 要求値)。 配備 AI で最も伸びしろの大きい領域 (= 攻撃順・DON配分・要求値設計が beam value 未モデル化)。

---

## 1. 攻撃順の理論

### 1-1. 基本: 低パワー → 高パワー (階段方式)
- **パワーは低い方から徐々に上げて攻撃する**。 高パワー先行は損。
  - 理由① **無駄ドン最小化**: 高パワーを先に出してライフ受けされると付けたドンが丸ごと無駄。 低い方から出せば無駄を最小化。
  - 理由② **効率**: 相手は安いカウンターから切る。 低パワーを先に通して安い札を吐かせ、 高パワーは後半に温存。
- **典型的失敗**: 「9000で攻撃 → 次に8000」はリーサル失敗の典型。 低い順なら通っていたケースが多い。
- **階段の具体例**: 場「5000×3 + 9000」+リーダー5000、 各キャラに2ドンずつ → `7000/7000/8000/8000/9000` の昇順で殴る。

### 1-2. 階段の「振り幅」公式
- **段差の最適 = 盾(ライフ)枚数 × 1000 + 1** まで。
  - 盾2枚なら段差2000まで許容 → 例 `7000-9000-9000-11000`。
  - 根拠: ライフ1枚から出るカウンター期待値が約800〜1000なので、 盾枚数ぶんの振れを織り込んだ段差にする。

### 1-3. ⚠ 諸説対立: 「階段」 vs 「フロントロード (最初に最強打点)」
明確な流派対立。 **両論併記**。
- **A説 (標準・階段/均等)**: 低→高 昇順、 または均等に振る。 グラインドで主流。
- **B説 (フロントロード)**: 語るボブル氏 —「**リーサルは階段でなく最初に最強打点が最適**」。 狙いは **相手にライフで受けるべき攻撃を選ばせない**。 最強打点を先に出すと相手は「9000をライフ受けか/カウンター守りか」の不利な二択を迫られる。
- **統合**: 両者とも「相手に有利な受けを許さない」同一目的の別アプローチ。
  - **通す攻撃を多く/相手手札を削るグラインド局面** → 低→高・均等
  - **リーサル1発の分岐を相手に押し付ける局面** → フロントロード
  - ブロッカー有無・ライフ枚数で使い分ける。

### 1-4. リーダーアタックを先か後か / キャラから殴るルール
- **原則: 攻撃可能なら『キャラ』から殴る** (トリガー除去ケア)。 先にリーダーで殴って KO/パワー参照除去トリガーをめくられると自分のアタッカーを失う。
  - **例外**: 相手が赤系でパワー参照除去トリガーを積むなら、 先に自アタッカーにドンを振って除去圏外まで上げてから殴る。
- **キャラが2体以上なら「まずリーダーで殴り、 相手の反応を見てから残りキャラの攻撃先を選ぶ」**説もある (情報取り優先)。 → トリガーケア優先か情報取り優先かで分岐。
- 格言: **「悩んだら攻撃。 悩んだら大きなキャラ (を狙う/を先に)。」** 迷ったらリーダーアタック (ほぼノーリスクで相手手札-1 or ライフ-1)。

## 2. DON!! の付与・情報戦

### 2-0. 前提ルール (正確に)
- 付与で **パワー +1000/枚**。 付与できるのは **アクティブなドンのみ**。
- **⭐ 付与 +1000 は「所有者のターン中のみ」有効** (公式 6-5-5)。 相手ターンには消える + そもそも付与不可 → **「守りを固めるためにドンを付けて残す」は無意味**。
- リフレッシュで付与ドンは全部アクティブに戻る (= 毎ターン振り直せる)。
- **メインとアタックは分離していない**。 登場/効果/DON付与/バトルを好きな順・好きなだけ行える → アタック前でも後でも付与できる。

### 2-1. 「ドン速度」 — 展開に使うか付与に使うか (IKE 氏の概念)
- **速いドン (付与)**: そのターンだけパワーが上がり要求値を即座に作る。 使い捨て。
- **遅いドン (キャラ登場)**: 恩恵に数ターンのラグがあるが、 盤面キャラは残って複数ターン効き続ける資産。
- **序盤は「遅いドン」が基本優位** (付与の過剰パワーはライフに吸われて無駄、 盤面キャラは要求値を積み上げる)。
  - 例 (4ドン): 速い=L9000アタック(要求+5000、 単発) vs 遅い=4c6000キャラ+L5000 (初動+1000だが次ターンから+2000要求が継続 → 2ターンで追いつく)。
- **終盤 (リーサル2ターン前〜) は逆転**: ライフ2-3では相手も高打点を受け始めるので付与で一気に要求値を作る。
- **速攻キャラのドン効率**: ドン+2000型 (3c3000ゾロ / 4cカタクリ) は使用ドン以上のパワーでバニラ採用価値大。 ドン+0型 (4ジョズ/7エース) は効率悪。

### 2-2. 集中 vs 分散 (付与の割り振り)
目的で使い分ける。
- **分散 (均等) が基本**: 複数攻撃を必ず通したい (リーサル/ブロッカーケア) なら、 まず全攻撃を均等に揃える。「5000→7000より6000→6000」で尖らせない方がカウンター消費を引き出す。
- **集中 (尖らせ) が強い場合**: 「千の位が偶数の攻撃が偶数体」ある時は振り分けた方が要求枚数UP (後述)。 ドン×X効果の発動、 ブロッカー1体で受け切れない高打点を作りたい時も集中。
- **中途半端配分は最弱**: 5キャラに1ドンずつ配ると全部が弱体化して何も通らない。

### 2-3. 情報戦・ブラフ (DON運用の勝負どころ)
- **⭐ 付与は攻撃宣言のギリギリまで確定・提示しない**。 事前割り振りはパワーラインも攻撃回数もバレる。 相手の反応を見てから量を決める柔軟性を最大化。
- **⭐ 攻撃を先に、 キャラ展開は後**。 先にキャラを出すと使ったドン・残りドン・手札が読まれる。
- **速攻キャラは出したターンにすぐ殴らない**。 先に他の攻撃を済ませてから速攻を出すと残りドンを読まれず奇襲。
- **あえて嘘の振り分けを見せる**: `7000→5000` で殴りつつ「次は9000かも」と思わせ、 7000をカウンターさせ5000をライフ受けさせる。
- **守り方でも手札が漏れる**: 「6000攻撃に1000カウンター2枚」= 「2000カウンターを持っていない」とバレる。
- **アクティブドンを残すこと自体がプレッシャー** (カウンターイベント/起動の構えか、 ブラフか読ませる)。

### 2-4. ドンをあえて残す「本当の」意味
付与+1000は相手ターン無効なので、 残す価値は次の4用途に限る:
1. **カウンターイベントのコスト源** (相手ターンに撃つにはアクティブドンが要る)
2. **起動/リアクション効果のコスト**
3. **ブロッカーの再起動** (アタック/ブロック時に自軍を起こす効果との併用)
4. **次ターンの展開リソース** (過剰打点はライフに吸われるだけ)

> ⚠ 保護目的の先付けは良い: 相手トリガー/効果に「パワー4000以下除去」が予測される時は、 4000キャラに1ドン付けて5000にし除去圏外へ逃がし、 他キャラで攻撃する。 = 具体的理由 (除去回避/リーサル到達/ブロッカー突破/opp leader へ届かせる) がある付与は◎、 理由なき均等先付けは✗。

## 3. 要求値 (カウンター要求値)

### 3-1. 定義と公式
- **要求値 = 相手がそのアタックを防ぐのに必要なカウンター値の合計**。
- **基本公式: `付与ドン数 × 1000 + 1000`** (対リーダー5000基準)。
- 防御側は常に3択: ①ライフ受け ②カウンター守り ③複数攻撃で片方受け・片方守る。 攻撃側は「どれを選んでも損」な配分を狙う。
- カウンターは1バトルに何枚でも重ねられる (2000×3で+6000)。

### 3-2. 要求値 → 手札要求枚数の段階表
| 上乗せ | 必要カウンター | 要求手札枚数 |
|---|---|---|
| +1000 | 1000×1 | 1枚 |
| **+2000** | 2000×1 or 1000×2 | 1〜2枚 |
| +3000 | 1000+2000 | 2枚確定 |
| **+4000** | 2000×2 or 4000イベント | 最低3枚 |
| +5000↑ | — | 最低3枚 |
- **オススメ帯は +2000↑ / +4000↑** (1枚で守れないラインで2枚以上を強要)。 端数 (+1000単発/+3000だけ) は非効率になりやすい。
- **要求値 ≠ 手札消費枚数**: 相手が高効率の2000カウンターを持てば同要求値でも少ない手札で守れる。 → 「要求値 × 相手手札の質・枚数」で考える。

### 3-3. 核心テクニック: 「相手パワー + 2000 × X」
- **X = 消費させたい手札枚数**。 相手に「通す」か「(1+X)枚使って守る」の二択を迫る。 **X = 相手残り手札数 → 物理的に防げない = 確定リーサル**。
- **2000刻みの根拠**: トリガー以外でライフ1枚から得られるカウンターは最大2000。 相手が最大効率(2000)で守っても2000刻みなら1攻撃ごと必ず手札を削れる。

### 3-4. 2000ライン・4000ラインという「壁」
- カウンター専用カードは主に **+1000 (多数) と +2000 (希少・強力)**。 テンプレ「2000×8〜12 + 1000×11〜18」、 デッキ50枚の合計カウンター値 ≒ 47000 (1枚平均 ≈940〜960)。
- **「千の位が偶数の攻撃が偶数体」だと振り分けた方が要求枚数UP**:
  - 4000キャラ2体で **15000パンチ1発 → 11000要求 (6枚)**
  - 同ドンを **5000+5000+13000 に振り分け → 1000+1000+9000要求 (7枚)** = 1枚多く吐かせる。
- **⚠ ブロッカーがいると逆に「均等割り」が正解** (振り分けると要求値が下がる)。 ブロッカー有無で振り方が逆転する (複数ソース一致)。

### 3-5. カウンターイベント (4000カウンター) への対処
- イベントカウンターはドンコストが要るが上昇値が大きい (+4000/+6000 も。 例: 雷鳴八卦 +4000)。
- 攻撃側: 相手が+4000イベントを持つと要求値4000でも1枚で受かる → **それを上回る要求 (+6000) や複数攻撃で枚数を割かせる**設計に。

## 4. リーサル計算・打点計算

### 4-1. 確定リーサルの思考フロー
1. **通す必要回数** (相手ライフ枚数 + 顔到達回数) を数える
2. **アタックできるキャラ数**を数える
3. **ブロッカーがいたら平均パワーを計算**
4. **相手のアクティブドンを確認** (カウンターイベント/起動の余地)
5. **トリガーを想定** (相手ライフからの除去/カウンター)
6. 要求値合計 > 相手の総防御力 なら **確定リーサル**
- **確定リーサルの定義**: 不完全情報でもあらゆる可能性を考慮してなお絶対勝てる = 要求枚数(値)が相手の手札総数(総カウンター値)を超えている。

### 4-2. ドン振り分けの核心: 「均等化 → ±2000で振る」
1. 必ず通したい複数攻撃は **まずパワーを均等にする**。
2. ライフ1枚のカウンターは最大2000なので **±2000以内で刻む** (差が2000超だと弱い攻撃を受け強い攻撃を守る逃げ道を与える)。
3. **平均値の求め方 (2体プラン÷2 と 3体プラン÷3 の中間)**:
   - 例: モリア9000+リーダー5000+10ドン=24000 → 2体なら÷2=12000、 3体(+1000キャラ)なら27000÷3≒9000 → 中間の **10000スタート**が最適 (500単位で切り下げ)。
4. **相手がどう対応しても要求値が一定になる配分が最強** (例 `10000-8000-8000` は守っても盾で受けても一律「盾込10000要求」)。
5. **小型・パワー0キャラも必ず計算に入れる**。 13ドン配分の最適解は `9000→12000` または `9000→7000→7000`。
- **⚠ ライフ1では平均でなく「最初のアタックを強く」** (トリガーで捲られるリスクがある盤面は1発目に打点を寄せて確実に押し込む)。

### 4-3. 相手カウンター最大値の見積もり (トラッシュ逆算)
- **理論上限 = 手札枚数 × 2000** (全部2000カウンターの場合)。 実際はもっと低いと補正。
- **トラッシュ逆算の実例**: 「2000カウンターが計6枚+その他10枚が既に落ちている」→「残り2000カウンターは多く見て4枚」→「相手手札7+ライフ1=8枚に2枚以上ある確率は極めて低い」と確率判断してリーサルを通す。
- これまで切った守り方 (6000に1000×2で受けた等) からも「2000カウンター無し」を読む。

### 4-4. ダブルアタック (ライフ2枚取り)
- **ルール**: 1回の攻撃でライフを2枚削る (2回攻撃ではない)。 相手ライフ1枚ならダメージ1に調整され勝利にならない。 **攻撃自体は1回なのでブロッカーで止まる**。
- **相手ライフ偶数 (2/4) の時に真価** (奇数だと1枚分余る)。 リーサル計算では「通す回数を1減らすカード」として数える。
- 代表: リーダーヤマト(常時)、 光月おでん(9c10000常時)、 ゲッコー・モリア(手札5枚以上)、 シャーロット・クラッカー。

### 4-5. 効果の発動順も要求値に効く
- 例 (カイドウの自ライフ焼却): 焼却する **前に攻撃**すると「8000+14000で盾1込10000要求」まで上げられるが、 **焼却後**だと「5000+10000で1000+6000要求」に留まる。 → 効果と攻撃の順番も要求値を左右する。

## 5. リーダーアタックの価値・攻撃回数

### 5-1. リーダーアタックの価値
- **利点**: 攻撃力5000以上のキャラはノーコストでリーダーへ攻撃できる。 5000以上を並べるだけで毎ターン無料の攻撃回数が増える。 4000以下もドン1で到達。
- **布石**: 相手の強キャラを効果で取れない時、 **まず5000でリーダーに殴ってカウンターを1枚削ってから**キャラ処理に動く。
- **⚠ 反対意見 (両論)**: 「リーダーに通す = 相手ライフ(将来の手札)が増える」。 あえて受けられるとカウンター資源を配ってしまい、 後でキャラ攻撃を弾かれる。 「リーダー攻撃=カウンターを切らせる」とは限らない。
- **統合**: 常にキャラ全処理も常にリーダー連打も誤り。 「削りたいのか/カウンターを吐かせたいのか」で使い分ける。

### 5-2. 攻撃回数を増やす重要性
- **2大軸**: 自分は「攻撃回数を増やす」、 相手には「攻撃回数を減らす」。
- **なぜ「弱い複数回」>「強い1回」か**: 10000も5000も防御されればライフ削りは「1」。 相手がブロック→攻撃回数ぶんライフを削れる、 相手がカウンター→攻撃回数ぶん手札を削れる。 **どちらに転んでも攻撃回数=相手リソースを削る回数**。

### 5-3. 序盤 vs 終盤で殴り方を切り替える (最重要の実戦原則)
| 局面 | 殴り方 | 狙い |
|---|---|---|
| **序盤** | **6000-6000** (同値・偶数) | カウンター"値"を最大要求・3択を強いて手札情報を読む |
| **終盤(リーサル前)** | **5000-7000** (階段) | カード"枚数"を最大要求・確実にリーサル |
- **序盤に5000-7000は間違い**: 相手が7000をライフ受けすると実要求は1000だけ = 情報も手札も取れない。
- **終盤に6000-6000は非効率**: 枚数を削りたい局面では5000-7000の方が1枚多く吐かせる。

### 5-4. 「攻撃してこない相手は怖くない」 — 攻撃圧力の本質価値
- 攻撃しなければ相手の手札は減らない。 攻撃こそ相手にカウンター/ブロッカーを強要して手札を吐かせる唯一の圧力。
- ブロッカー持ちも守りに徹するより攻撃してテンポを取り、 **2つの仕事 (攻撃の的 + アタッカー)** をさせる。
- 攻撃には「受けられると相手ライフ(将来の手札)が増える」デメリットも常にある → **「今ここで手札を吐かせる圧」と「相手ライフを増やすリスク」を毎回天秤に**。 ただし圧をかけ続けなければリソース差はつかない ([[feedback_ai_too_passive_attack_pressure]])。

## 6. 盤面圧力・テンポ・レスト管理
- 序盤に DON でキャラを横並べして攻撃回数を稼ぐ。 サーチ/ドロー持ちを並べてリーダーに殴ると盤面圧力を維持しながら相手手札を枯らせる。
- **相手がレストになるまで自分の5000未満キャラはアクティブに保つ** (無駄なレストは削られる隙)。
- 相手のレストキャラは **弱いキャラ (ドン節約) で撃破**して隙を突く。
- カードはマナカーブ通りに自動で出さず「いつ出せばすぐ使えるか」で使いたいターンにプレイ (予測されにくい脅威 = テンポ優位)。
- **横展開は全体除去に弱い** → 「次ターン生き残るキャラ」「除去されても登場時効果で仕事するキャラ」を意識。

## 7. ブロッカー突破・除去との組み合わせ

### 7-1. ブロッカーの本質と弱点
- **本質価値**: 「要求値がどれだけ大きくても1枚のブロッカーで解決できる」。 1コスト出し1ドンレストで大きなカウンター値を節約。
- **弱点 (突破口)**: ①攻撃前に場にいる必要 (事前 KO/レストで無力化) ②登場に手札1枚 ③低パワーだと攻撃に使えない ④**強い攻撃がない対面 (5000連打) では腐る**。

### 7-2. ブロッカー突破の3系統
1. **高パワーで踏み越える** (6000以上で殴れば低パワーブロッカーはバトルで割に合わない)
2. **除去する** (KO・バウンスで先処理してから本命を通す。 効果除去はアタック消耗より効率的)
3. **数で攻める** (複数回攻撃でブロッカー枚数を上回る。 数体で消費させ本命を最後に通す)

### 7-3. ブロッカー釣り出し (攻撃順の技術)
- **「相手にとって一番強い攻撃が分からない状況」を作る**のが核心。 `7000→5000` の順で殴り「次が9000かも」と思わせると相手は弱い攻撃(5000)にブロッカーを使いにくく本命を通しやすい。
- **5000から殴り始める**と相手は「ブロックしたら取られる/次に強い攻撃が来るかも」と迷い情報を吐く。

### 7-4. 除去との組み合わせ
- **「リーダーより強いカード」は効率的に除去** (無駄トレードよりKO/バウンス優先)。 除去できないなら早めにプラン切替でリソース垂れ流しを防ぐ。
- 近年の上級常識: **攻撃前にブロッカーをレスト・キャラを KO してからリーサル計算**。
- **除去偏重デッキ相手の裏返し**: 相手が KO/レスト多用型なら **あえてブロッカーを出さず**、 ドローで手札を増やす/自分もアグロを取って除去札を腐らせる。

---

## 8. 相手のライフ受け・トリガーのケア
- **無理にライフを削らない場面もある** (トリガーで返されるリスク)。 相手残ライフ × トリガー率を計算。
- **トリガー期待値の目安**: デッキにトリガー2枚で約20%、 5枚で約40%、 8枚で約60% がライフに含まれる。 残ライフが多いほど詰めると強トリガーを踏むリスクUP。
- **ライフはHPでなくリソース**: 序盤のライフは安い (受けて+1card)。 ライフ5→3までは安いチップは気軽に受けてよいが、 **理想は2ライフ以上維持、 0ライフ厳禁**。

## 攻撃前チェックリスト (6要素)
攻撃順を決める前に総合判断: ①相手手札枚数(=カウンター総量の上限) ②相手ライフ枚数(トリガー込) ③トリガー(KO・回復)警戒 ④ブロッカーの数とパワー ⑤相手アクティブドン数(イベントカウンター警戒) ⑥想定カウンターイベント。
- **通常/グラインド** → 低→高・均等、 キャラから攻撃、 序盤6000-6000
- **リーサル** → 均等化してから±2000で振る、 段差「盾枚数×1000+1」、 どう受けても要求値一定の配分、 終盤5000-7000
- **偶数体×偶数千の位** は振り分けで壁を突く (**ただしブロッカーありは均等**)
- **付与は宣言ギリギリまで見せない、 攻撃を先に・展開は後**

## 諸説対立まとめ (両論併記)
1. **リーサルの攻撃順**: 低→高/階段 (主流) vs フロントロード=最初に最強打点 (語るボブル)。 グラインドか一発リーサルか・ブロッカー有無で使い分け。
2. **序盤に同値(6000-6000)か階段(5000-7000)か**: 前者=カウンター値を吐かせる、 後者=枚数を削る/確実に通す。 序盤=同値・終盤=階段が総意。
3. **均等 vs 尖らせ**: 必ず通したい/守りにくくしたいなら均等、 手札を最大削りたい/端数を稼ぎたいなら尖らせ。 **ブロッカー有無で逆転**。
4. **リーダーアタックの価値**: ノーコストで削れる長所 vs 受けられると相手手札+1の短所。 状況次第。
