## 全ドキュメントを貫く統一原則 (これだけは絶対)

すべての攻略ソースが一致して強調する、他のすべての技術の土台になる原則。

### 1. これは「ライフを削る」ゲームではなく「手札 (リソース) を削り合う」ゲーム
- **1ターンのリソース回復は非対称**: DON!! は毎ターン +2 (最大10) 回復するが、 ドローは 1 枚。 ゆえに **手札こそ希少リソース**で、 勝敗は最終的に **手札差**で決まる。
- **守る = 手札を1枚失う行為**。 守るたびに自分の手札が減り、 相手の残りカウンター1枚の価値 (= 相手のリーサル達成力) が上がる。
- **攻撃 = 相手にカウンター/ブロッカーを強制消費させる圧力**。 「攻撃してこない相手は怖くない」 — 攻撃を止めると相手は防御に使うはずの手札を展開に回せる。 **圧をかけ続けなければリソース差は決してつかない** ([[feedback_ai_too_passive_attack_pressure]])。

### 2. ライフ = 第二の手札
- **リーダー攻撃をライフで受ける = 手札が1枚増える** (+ トリガー抽選)。 ライフは「後払いの手札」。
- **最強の攻撃こそライフで受ける**: どんな巨大攻撃でもライフ受けなら消費は「ライフ1点」。 中打点を複数カウンターで守るとカウンター値を大量消費する。
- 序盤はビビらず受けて手札に選択肢を蓄える (ライフ5なら3ダメまで気軽に、 状況次第で2まで)。 **0ライフは厳禁** (相手が全ドン1体集中でカウンター不能負け)。

### 3. NNA (必要攻撃回数) にすべてを翻訳する
- **`手札枚数 + ライフ×2 + 1 = 相手を倒すのに必要な5000攻撃の最大回数`**。 ゲーム開始時 ≈ 最大15。 **自分の NNA を先に1にするゲーム**。
- **非対称性**: パワー10000で殴っても5000で殴っても、 受けられればライフは1しか減らない → **強い1回 < 弱い複数回**。 これが低コスト横展開が強い構造的理由。

### 4. 要求値 = 付与ドン数 × 1000 + 1000
- 相手にそのアタックを防ぐのに要求するカウンター値。 +2000〜+4000 を強い、 **相手が1枚で守れないライン**を作る。
- **相手パワー + 2000 × X** (X = 吐かせたい手札枚数)。 X = 相手残り手札数 にすれば物理的に防げない = 確定リーサル。

### 5. 情報を渡さない / 相手から見える世界で考える
- DON 付与は宣言ギリギリまで見せない、 攻撃を先に・キャラ展開は後、 登場時効果のないキャラは後出し、 アタックは小さい方から。 「自分から見た世界」だけでなく **相手から見える世界**で自分の狙いを悟らせない。

## このプロジェクト (配備 AI) への含意

- **守り側は整備済**: 過剰防御 (8e0d45d) / 過剰カウンター (8b43070) / 対象不在イベント (ebcd744, dfbdb19) を撃たない = 人間の「最小限・無駄撃ちしない」に一致。
- **攻め側が最大の伸びしろ (❌ フロンティア)**: DON 付与タイミング (攻撃前全キャラ均等付与をやめる)・攻撃順 (低→高)・要求値設計。 多くは **beam の value が tempo/情報/counter-drain をモデル化していない**ため粗い。
- **単発ヒューリスティックは頭打ち** (force-attack 順の A/B Δ0 が実証)。 これらの操作術を **beam value / 探索の score 項** ([[project_block_value_architecture]]) or **Claude 教師 demonstrate との一致** ([[project_claude_teacher_data_collection]]) で埋めるのが本丸。
