## 0. 基本方針 (すべての土台)
- **リソースを認識する**: ドン!! / キャラ / 手札 / ライフ の4リソース。 各手が「どのリソースをどれだけ使い、 何を得るか」で判断。
- **攻撃回数が多い方が勝つ**: 相手のリソース(手札=カウンター)を早く削り切るゲーム。 攻撃回数を増やす盤面を作る。 ⚠ AI は force-attack で攻撃するが順番/DON配分が粗い。
- **盤面を作る/作らせない**: 自分は展開、 相手には展開させない (除去/圧)。
- **迷ったらリーダーアタック**: ほぼノーリスク・ノーコスト。 相手手札-1 (カウンター強制) or ライフ-1 を得る。 ターン最初にやる。 ✅ AI は force-attack で実装済。

## 1. マリガン
- **迷ったらキープ**。 1枚でも欲しいカードがあればキープ。
- **対面ごとに「欲しいカード」を2枚くらい事前に決める**。 漠然と上振れ狙いでマリガンすると大抵悪くなる。
- **サーチカード単体はマリガン** (5枚引き直す方が効率的)。
- **カウンター有無は基準にしない**: メインアタッカーが無くカウンター値だけ高い手はマリガン。 カウンターレスでもメインカードが多ければキープ。
- ⚠ AI: `decks/<slug>.analysis.json` の mulligan_keep_card_ids + imitation prior で判定。 対面別 keep はまだ粗い。

## 2. ドン!! 付与 (タイミング・割り振り)
- **理由なき「攻撃前に全キャラ均等付与」は もったいない + 手の内バレ**。 ❌ AI は現状これをやっている (計測済 2026-07-18)。
- **DON は残して柔軟性/情報優位を持つ**: 素パワーで攻撃し、 相手の守りを見てから通したい攻撃に後から回す。 「どの攻撃を守ればカウンター効率が良いか」相手が読めなくなる。
- **付与に具体的理由がある時だけ先付け ◎**:
  - **除去回避**: 相手のトリガー/効果に「パワー4000以下除去」等が予測される時、 4000キャラに1ドン付けて5000にし除去圏外へ。 他キャラで攻撃。
  - **リーサル到達 / ブロッカー突破 / 攻撃をopp leaderに届かせる**。
- **リーダーへの付与が DON あたり drain 効率 最良** (フリーで殴れる leader を 8000 にする > 小キャラに3ドンで5000)。 ✅ AI: lethal_pressure 時のみ leader boost。
- **均等分散は基本のデフォルトだが最適ではない**: 強弱をつけた攻撃が有効。 集中は リーサル/特定ブロッカー突破時のみ。
- ⚠ AI: `_is_attach_don_wasteful` で非攻撃キャラへの付与は抑制済。 だが「残す価値/先付けの手の内バレ」は value 未モデル化 = ❌ フロンティア。

## 3. 攻撃 (順番・要求値)
- **要求値 = 付与ドン数×1000 + 1000** (相手に要求するカウンター値)。 2000以上、 できれば4000以上を強いる。
- **非リーサル(グラインド)は 低パワー→高パワーの順**: 各攻撃が前以上の要求値を積み、 相手カウンターを効率的に枯らす。 高パワー先行はライフ受けでドンが無駄。 ⚠ AI: force-attack path は低→高に修正済 (commit 3694b09) だが beam 駆動分は未対応 = ❌。
- **フラット(均等)に殴らない**: 強弱をつける。
- **相手が最強攻撃をライフで受けられない状況を作る** (受けられると意味が薄い)。
- **序盤 6000-6000 / 終盤 5000-7000** が目安 (序盤=カウンター値要求、 終盤=手札枚数要求)。
- ⚠ **リーサル時の順番は諸説** (低→高で枯らす説 vs 最初が最強説)。 リーサル計算は「複数プランの平均から最適攻撃値、 500以下切り捨て」。 ✅ AI: lethal_planner が別途厳密計算。

## 4. カウンター / 防御 (切る・受ける判断)
- **カウンターは最小限**: 「その攻撃が(以降含め)一番低打点 かつ 同値も受けない」時だけ切る。 ✅ AI: 過剰カウンター防止 (完全防御済に切らない、 commit 8b43070) + 過剰防御防止 (効果を不要時に撃たない、 8e0d45d)。
- **序盤の低打点は受け、 終盤の高打点にカウンター温存**。
- **ライフで受ける = 手札が増える**: 要求値が高い攻撃をライフ受けすれば合計カウンター値を節約。 手札を使ってライフを守ると「手札2枚分」のアド損 (守った1枚 + 受ければ増えた1枚)。
- **手札を守る意味があるキャラ/局面でだけ守る**: 「次ターン勝つ」「脅威的キャラ」を基準に。 点数稼ぎでカウンター消費しない。
- **手札=選択肢**: カウンターを使いすぎると次ターンの選択肢が枯れる。
- **要求値計算(守備)**: 盾なしは全ドン付けで単純計算。 千の位が偶数の攻撃が偶数体なら振り分けで要求値上昇。 盾複数は均等割り付けから、 階段は「盾枚数×1000+1」が最適振り幅 (盾1枚の期待値≈1000)。

## 5. ブロッカー
- **大型連打デッキには有効、 5000連打には無効**。
- **アタッカー兼用ブロッカーは積極的に殴る**。 純ブロッカーは守備役として温存 (攻撃で消費しない)。 ✅ AI: force-attack で非ブロッカー優先。
- **除去リスクを考慮した配置**。 相手の除去が腐る盤面を作る。
- **ブロッカー登場より先にリーダーアタック**を済ませる (相手トリガー誘発前に殴る)。

## 6. 盤面 / リソース管理 / 色別
- **次の相手最強ムーブを想定**して動く。 次々ターンまでのライフ削り計画を持つ。
- **相手の除去(KO)カードが腐る状況を作る**。
- **色別**: 赤系=小〜中型を並べる (低ドン効率に対抗)。 青系=戻されて良いキャラを複数 (大型は温存)。 緑系=エサキャラでレスト効果を強制し本命を遅延。
- **置物(アタック時効果)は効果を無駄撃ちせずレスト維持**が強い。 ✅ AI: 対象不在イベントを撃たない (ebcd744/dfbdb19)。

## 7. 情報戦 / 上達
- **ドン配分/プレイで手の内を晒しすぎない** (残す・後出し)。 速攻キャラは後出しが読まれにくい。
- **素直なプレイが基本** (特に序盤〜中盤)。 奇をてらう前に定石を徹底。
- **相手の初手カウンターの切り方から手札を推測**して攻撃パターンを調整。

## AI 実装の総括 (人間facing品質の観点)
- ✅ **守り側は整備が進んだ**: 過剰防御/過剰カウンター/対象不在イベント を撃たない (人間の「最小限・無駄撃ちしない」に一致)。
- ⚠❌ **攻め側 (DON付与タイミング・攻撃順・要求値設計) が最大の伸びしろ**: 現状「攻撃前に全キャラ均等DON付与」等、 人間の定石から外れる。 force-attack path は一部修正したが、 複数攻撃の順番/DON配分の多くは **beam の value が tempo/情報/counter-drain をモデル化していない**ため粗い。
- **方針**: これらの操作術を **beam value / 探索の score 項** or **人間 demonstrate との一致** で埋めるのが本丸 ([[project_block_value_architecture]] / [[project_claude_teacher_data_collection]])。 単発ヒューリスティックは頭打ち (force-attack 順の A/B Δ0 が実証)。
